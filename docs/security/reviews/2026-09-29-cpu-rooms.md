# Differential security review: rooms against the CPU (#55, part 2)

**Date:** 2026-09-29 · **Scope:** `feat/cpu-rooms` vs `main` · **Strategy:** DEEP. This is a protocol change (the new request body, so `sharp-edges`) and a room-access change (a seat no client may take, so `differential-review`), both mandatory per `CLAUDE.md`.

## Change

- **Room creation:** `POST /api/rooms` accepts an optional JSON body `{"opponent": "friend" | "cpu"}`. For `cpu`, the room's `/init` seats the CPU in seat 1.
- **The CPU:** the room service makes the CPU place a random fleet and fire after a 0.9 s pause, driven by the room alarm.

## Risk classification

| File | Risk | Why |
|---|---|---|
| `src/naval/worker/entry.py` | HIGH | Reads a request body on a public, unauthenticated endpoint |
| `src/naval/protocol/requests.py` | HIGH | New input schema |
| `src/naval/rooms/room.py` | HIGH | A seat no client may take; flag and rematch rules change for CPU rooms |
| `src/naval/rooms/service.py` | MEDIUM | A new actor mutates the game on handled messages and alarms |
| `src/naval/rooms/codec.py`, `src/naval/worker/game_room.py` | MEDIUM | Persistence and `/init` |

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | MEDIUM | As first written, the Worker read the whole body (`request.text()`) whenever `Content-Length` was missing. A chunked body could then be buffered up to the platform limit inside an isolate other requests share. | Fixed before review: only a body that declares a `Content-Length` of at most 256 bytes is read. A request without one has no body (a friend room), and a larger declared length gets 400 without reading. Checked against `pywrangler dev` with a 5 KB chunked body: 201, body unread. |
| 2 | LOW | A chunked body is ignored rather than refused, so a non-browser client that sends `{"opponent": "cpu"}` chunked gets a friend room. | Accepted: browsers send `Content-Length` for a string body. The request is bounded either way and gains the sender nothing. |
| 3 | INFO | The CPU seat has a token hash like any seat, so a join with the right token would take it. | Not reachable: the token is 32 bytes from `secrets` and is never delivered or logged. The CPU seat has no `join_hash`, so it cannot be reclaimed through a join id. A third visitor gets `room_full` (integration test `test_the_cpu_plays_back_and_its_seat_cannot_be_taken`). |
| 4 | INFO | Could the CPU see the person's fleet? | No: `choose_shot` receives only `shots_received` and `sunk_ships` of the person's board, the same facts the per-seat view gives a player. The CPU's own fleet reaches the person only in the `game_over` view, as for any opponent. |
| 5 | INFO | Could a player foresee the CPU's fleet or shots? | The Worker uses `random.SystemRandom()` (the service default), not a seeded generator. |
| 6 | INFO | On a rollback, the previous version cannot load rooms whose CPU seat stores `cpu: true`. | Accepted: only CPU rooms are affected, and rooms expire after an hour idle. People's seats never store the key. |

No HIGH findings.

## Evidence

- **Validation (control 3):**
  - `CreateRoomRequest` is strict and `extra="forbid"`, with a closed enum.
  - `tests/protocol/test_requests.py` covers the refusals: unknown or case-changed values, extra fields, non-objects, invalid text and oversize.
  - Integration tests cover 400 on malformed bodies and 201 without one.
- **Ordering:** the Origin check and the per-IP room-creation limit run before the body is read. A CPU room costs the same rate-limit token as any room.
- **Bounded work:**
  - The CPU acts only in a room with a person seated, at most once per turn it is given.
  - The alarm deadline includes the CPU's turn only while it is the CPU's turn in the battle.
  - A CPU room without a person never schedules CPU work, and idles out after an hour.
- **Isolation (control 6 equivalent):** views are unchanged, and the per-seat view test still passes. Nothing is delivered to the CPU seat (`connected_seats()` excludes it).
- **Real Worker:** 33 integration tests pass against `pywrangler dev`, including the CPU answering through the Durable Object alarm.

## Coverage limits

- The chunked-body check ran against the local runtime. Cloudflare's edge may normalise such requests differently, and the fix does not depend on how it does.
