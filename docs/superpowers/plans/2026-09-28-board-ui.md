# Board UI: ships, placement, animations, 3D (#35) Implementation Plan

> Executed task by task in a single session. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ships look like ships on the board, placing them is direct (drag and drop, tap to select and rotate), shots land with short animations, and the result swings in with a CSS 3D turn — all without hurting performance or accessibility.

**Architecture:** A `ships.js` module draws a flat SVG silhouette per ship kind. `Grid` gains a ship layer: an absolutely positioned grid child spanning the 10×10 cell area, painted before the cells, so intact ship cells are transparent over their hull while hit and sunk cells keep their full-cell marks on top. `PlacementView` keeps the keyboard path and adds a select model (select, move, rotate in place) plus pointer-event drag and drop through a small `ShipDrag` helper. `BattleView` marks the newest shot (all cells of a newly sunk ship, staggered) and CSS animates by outcome with transform and opacity only.

**Tech Stack:** Vanilla ES modules, inline SVG built with `createElementNS`, CSS 3D transforms, Pointer Events, Playwright.

## Global Constraints

- No inline scripts, styles or handlers; ship positions are set through CSSOM custom properties (`element.style.setProperty`), which the CSP allows.
- Flat poster style: no shadows (the existing inset focus ring excepted), no rounded chrome, colours from tokens; each cell state keeps a distinct shape, never colour alone.
- Animations: transform and opacity only, 250–600 ms, `ease-out`; only the newest shot animates; `prefers-reduced-motion: reduce` removes them and final states never depend on them.
- Keyboard: every placement action stays possible without a pointer (dock buttons, arrow keys, Enter, R).

### Task 1: Ship silhouettes and the ship layer

**Files:** Create `public/js/ships.js`; modify `public/js/grid.js`, `public/styles.css`, `public/js/placement.js`, `public/js/battle.js`; test `e2e/board.spec.js`.

- `shipSvg(kind, orientation)` returns an `<svg class="ship-art">` with a `viewBox` of `len×10` by `10` units (swapped when vertical, drawn through a `rotate(90)` group): a blue hull with a pointed bow, plus ink and white details per kind (carrier flight-deck stripe and island; battleship three turrets; cruiser two; submarine slim hull and conning tower; destroyer one).
- `Grid.setShips(placements, { selected })` renders one `.ship` per placement inside `.ship-layer` with `--row`, `--col`, `--len` and an orientation class; `.ship.is-selected` fills the hull yellow.
- CSS: `.board { position: relative }`; `.ship-layer { position: absolute; grid-row: 2 / span 10; grid-column: 2 / span 10; pointer-events: none }`; ship boxes by percentages; `.board .cell.state-ship { background: transparent }` so the hull shows; hit and sunk rules come later in the file and still paint over.
- The hit and sunk crosses become a drawn mask (the fonts lack U+2715), in the cells and the legend.
- E2E: the placement grid shows one ship element per placed ship with the right length and orientation; own board in battle shows the fleet; a hit cell on the own board still reads "hit" (aria-label) and paints over the hull.

### Task 2: Placement interaction

**Files:** Create `public/js/ship-drag.js`; modify `public/js/placement.js`, `public/index.html` (help text), `public/styles.css`; tests in `e2e/board.spec.js`, existing placement flows in `e2e/*.js` keep passing.

- Model: a ship is selected from the dock or by clicking it on the grid (it stays on the board, drawn selected). A water cell places or moves the selected ship. Clicking the selected ship again, or **R** / **Rotate**, rotates it in place when it fits (otherwise a status message). With nothing placed selected, **R** changes the orientation for the next placement.
- Dock buttons show the ship's silhouette instead of pips.
- Drag and drop with Pointer Events from the dock or from a placed ship: starts after 6 px of movement (taps stay clicks), previews where the ship will land keeping the grab offset along the hull, drops on a valid spot, cancels elsewhere; the click that ends a drag is swallowed. `touch-action: none` only on dock ships and placed ship cells.
- E2E: drag a ship from the dock onto the grid; drag a placed ship to another spot; clicking a selected ship rotates it; the keyboard-only placement test still passes.

### Task 3: Shot animations and the 3D result

**Files:** modify `public/js/battle.js`, `public/js/grid.js` (`--i` stagger), `public/styles.css`.

- Miss: a ring grows out of the dot and fades (`::before`, 600 ms).
- Hit: the cell turns over (`perspective(300px) rotateX(-90deg)` → none, 320 ms) and a short burst fades.
- Sunk: every cell of that ship turns over in order, 60 ms apart (`--i`).
- Both boards: your shot on the enemy grid, the opponent's shot on yours.
- The result title swings in around its left edge (`rotateY`), like a flag hoisted into view.
- E2E: a new shot's cell carries `is-new` for its outcome; with `reducedMotion: "reduce"` the final marks are visible immediately.
